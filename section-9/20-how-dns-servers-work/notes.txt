📓 How DNS Server Works
🔍 DNS Lookup Flow
DNS ka kaam simple hai — domain name → IP address ka translation. Is process ko DNS Resolution bolte hain.
Test karne ke liye command:
nslookup
📶 IPv6 Preference
Agar IPv4 & IPv6 dono available hain, system IPv6 prefer karega (kyunki addresses zyada available hain aur performance better ho sakti hai).
🔐 Direct IP Access Control
Agar tum direct IP se site open karte ho (e.g., http://142.250.182.14), to ye depend karta hai website owner ne allow kiya hai ya block.
🌐 Common Public DNS Servers
1.1.1.1 → Cloudflare DNS
8.8.8.8 → Google DNS
🛠 DNS Resolution Steps
1️⃣ Check Browser Cache
Browser pehle apne cache me dekhta hai ki kya is domain ka IP already stored hai.
2️⃣ Check OS Cache
Agar browser me nahi mila to OS ke DNS cache ko check karta hai.
3️⃣ Ask DNS Resolver
OS ek Recursive DNS Resolver (e.g., 1.1.1.1, 8.8.8.8) ko query karta hai.
Ye resolver pehle apna cache check karta hai.
4️⃣ Query Root Server (.)
Agar cache miss ho, resolver Root DNS Server se poochta hai.
Root server TLD server ka address deta hai (e.g., .com).
5️⃣ Query Top-Level Domain (TLD) Server
Resolver TLD server se poochta hai ki requested domain ka Authoritative Name Server kaunsa hai.
6️⃣ Query Authoritative Name Server
Ye server domain ka actual IP address rakhta hai.
Ye resolver ko correct IP return karta hai.
7️⃣ Browser Connects to Web Server
Browser IP se connect karke website load karta hai.
📡 What is a Name Server?
Ek specialized server jo domain name ka location batata hai.
DNS records store karta hai:
A record → IPv4 address
AAAA record → IPv6 address
MX record → Mail server info
Authoritative Name Server → Domain ka final truth source.
⏳ What is TTL (Time To Live)?
TTL ek value (seconds me) hai jo batati hai ki DNS record kitni der cache me rakha ja sakta hai.
Example: TTL = 300 → record 5 minutes ke liye cache me rahega.
Short TTL → Updates jaldi reflect honge but DNS queries zyada hongi.
Long TTL → Performance better but changes reflect hone me delay.
⚡ Summary:
DNS resolution ek step-by-step query process hai jo cache se start hota hai, phir Root → TLD → Authoritative Name Server se IP find karta hai. Name servers DNS ka backbone hain aur TTL caching ka control karta hai.

How DNS Server works ?
 DNS Lookup Flow

 You can test DNS resolution using the command:
 nslookup 

 📶 Preference for IPv6
 If both IPv4 and IPv6 DNS servers are available, your laptop will prefer IPv6 (for better performance and more available addresses).

 🔐 Direct IP Access Control
 Accessing a site via direct IP (like http://142.250.182.14) depends on the website owner—they can allow or block this.

 🌐 Common DNS Servers
 1.1.1.1 → Cloudflare DNS
 8.8.8.8 → Google DNS

 DNS Resolution Steps
Check Browser Cache
 Browser checks if it has the IP for the domain stored.
Check OS Cache
 If not found in the browser, the system checks the Operating System's DNS cache.
Ask DNS Resolver (e.g., 1.1.1.1 or 8.8.8.8)
 The recursive DNS server checks its own cache.
Query Root Server
 If the cache misses, it contacts the Root DNS Server (.).
 The Root Server responds with the IP address of the Top-Level Domain (TLD) Server (e.g., .com).
Query Top-Level Domain Server
 Your DNS server asks the TLD Server for the IP of the Authoritative Name Server for the requested domain (e.g., google.com).
Query Authoritative Name Server
 This server knows the actual IP of the domain.
 It responds with the correct IP address.
Browser Connects to Web Server
 The browser now connects to the web server using the IP and loads the website.

 What is a Name Server?
 A Name Server is a specialized server on the internet that handles queries about the location of domain names.
 It's part of the DNS system and stores DNS records (A, AAAA, MX, etc.) for a domain.
 Authoritative Name Servers are the final source of truth for a domain’s IP address.

 What is TTL (Time To Live)?
 TTL is a value (in seconds) that tells how long a DNS record can be cached.
 For example, if TTL = 300, the record can be cached for 5 minutes.
 A shorter TTL means more frequent updates but more DNS traffic. A longer TTL improves performance but may delay changes.
