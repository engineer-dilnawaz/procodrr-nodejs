4. Ports, Network Interfaces, MAC Addresses & Firewalls

The IP address gets data to the right machine. The port number gets it to the right program on that machine. A network interface is one of the machine's connections to a network, a MAC address is the hardware ID of one network card, and a firewall decides which traffic may pass.

🤔 The Problem

One server runs many programs at once: a web server, a database, SSH. A packet that reaches the right IP still needs to reach the right program, so every service listens on its own port. And when your API "works on my machine but not from my phone", the cause is almost always one of three things on this page: the port, the address the server listens on, or a firewall.

TermOne line
PortA number from 0 to 65535 that picks the program on a machine
Socket addressIP + port together, e.g. 203.0.113.10:443
Ephemeral portA temporary port the OS gives the client side of a connection
Network interfaceOne connection point to a network: Wi-Fi, Ethernet, loopback, VPN…
MAC addressThe 48-bit hardware ID of one network interface
FirewallAllows or blocks traffic using rules (port, IP, program)

Port Numbers

The IP picks the machine; the port picks the program on it.

203.0.113.10 : 443
└ which machine ┘ └ which program (here: the HTTPS server)

Ports are a transport-layer idea: TCP and UDP headers carry the port numbers, while the IP header only carries addresses.

RangeNameUsed for
0 – 1023Well-known (system) portsStandard services. On Linux, binding them needs root rights
1024 – 49151Registered (user) portsApplications and databases (3000, 5432, 27017…)
49152 – 65535Dynamic / ephemeral portsTemporary client-side ports (Linux uses 32768–60999 by default)

Every connection has two ports. When your browser opens https://example.com, the OS gives the browser a random ephemeral port, say 63813, and connects it to the server's port 443. A connection is identified by four values: client IP, client port, server IP, server port. That is how one server port can serve thousands of clients at the same time.

  • ➤ Two different programs on ports 3000 and 4000 of the same machine is fine.
  • ➤ Two programs listening on the same port and address is not possible.
    • The second one fails with EADDRINUSE.
  • ➤ Port 65536 does not exist.
    • Ports are 16-bit numbers, so the biggest is 65535.

Checked on Node 24:

const http = require("node:http");

http.createServer().listen(3000);
http.createServer()
  .listen(3000)
  .on("error", (err) => console.log(err.code, "→", err.message));
// EADDRINUSE → listen EADDRINUSE: address already in use :::3000

An out-of-range port fails straight away, before anything is opened:

require("node:http").createServer().listen(65536);
// RangeError [ERR_SOCKET_BAD_PORT]: options.port should be >= 0 and < 65536. Received type number (65536).

Network Interfaces

Each connection point has its own IP; listen() picks which ones accept.

A network interface is one connection point between a device and a network. A normal laptop has several, and each has its own IP address.
InterfaceWhat it is
Wi-Fi adapterWireless link to your router
Ethernet adapterWired link
Loopback (127.0.0.1, ::1)Virtual: the machine talking to itself. Traffic never leaves the computer
Virtual adaptersMade by VPNs, Docker, WSL and virtual machines
const os = require("node:os");

for (const [name, addresses] of Object.entries(os.networkInterfaces())) {
  for (const a of addresses) {
    if (a.family === "IPv4") console.log(name, a.address, a.internal ? "(internal)" : "");
  }
}
// Example output on Windows (your names and numbers will differ):
// WiFi 192.168.1.10
// Loopback Pseudo-Interface 1 127.0.0.1 (internal)
// vEthernet (WSL (Hyper-V firewall)) 172.20.48.1

The host you pass to listen() picks which interfaces accept connections (each row checked on Node 24, Windows):

server.listen(3000, host)Who can connect
"127.0.0.1"Only programs on the same machine, over IPv4
"0.0.0.0"Every IPv4 interface: same machine, your LAN, and the Internet if routed and allowed
(no host)Node uses :: when IPv6 is available: every interface, IPv6 and IPv4
"localhost"Only the address localhost resolves to first. On Windows that was ::1, so 127.0.0.1 was refused
  • ➤ Testing your API from your phone on the same Wi-Fi: listen with no host (or 0.0.0.0) and open http://<laptop's LAN IP>:3000.
  • ➤ listen(3000, "127.0.0.1") and then calling it from your phone does not work.
    • The phone's request arrives on the Wi-Fi interface, which is not listening: connection refused.

➡️ localhost usually resolves to ::1 first. If a server listens only on 127.0.0.1 and a client connects to localhost, Node 20+ (and 18.18+) quietly tries the IPv4 address next. Node 17–19 could fail here with connect ECONNREFUSED ::1:27017, a well-known MongoDB error. Writing 127.0.0.1 in connection strings avoids the question.

MAC Addresses

The hardware ID of one network card, used only inside the LAN.

A MAC address (Media Access Control) is the hardware ID of one network interface, set by the manufacturer. Switches use it to deliver data inside a local network.
  • ➤ 48 bits (6 bytes), written in hexadecimal: 00:1a:2b:3c:4d:5e.
    • Windows shows 00-1A-2B-3C-4D-5E as "Physical Address" in ipconfig /all.
  • ➤ The first 3 bytes identify the manufacturer.
  • ➤ The Wi-Fi card and the Ethernet port of one laptop have different MAC addresses.
IP addressMAC address
IdentifiesWhere a device is on a networkOne specific network card
Given byRouter, ISP or DHCP (software)The manufacturer (hardware)
Changes when you join another networkYesNo
TravelsEnd to end across the Internet, in every IP packetOnly within the local network
Size32 bits (IPv4) / 128 bits (IPv6)48 bits
OSI layer3 (network)2 (data link)
  • ➤ The switch in your office is using MAC addresses to send a frame to the right computer.
  • ➤ "A website can see my MAC address" is not true.
    • MAC addresses are not part of IP packets; they never leave your local network.
  • ➤ "A MAC address can never change" is not quite true.
    • The hardware one doesn't, but phones (Android 10+, iOS 14+) show each Wi-Fi network a random MAC by default, for privacy.

Firewalls

Rules on port, IP and program decide which traffic gets through.

A firewall watches traffic coming in (inbound) and going out (outbound) and allows or blocks it using rules. It usually sits between a trusted network and an untrusted one, such as the Internet.
DirectionUsual defaultExample rule
InboundBlocked, except replies to connections you started"Allow TCP 443 from anywhere"
OutboundAllowed"Block this program from the Internet"

Rules match on port, IP address (or range) and program. A well-set firewall blocks almost every port by default and opens only the few a service needs.

➡️ In the cloud the same idea is called a security group (AWS): a list of inbound and outbound rules attached to a server, e.g. "allow 22 from my IP, allow 443 from anywhere".

  • ➤ Web server: open 80 and 443 to everyone, 22 only to your own IP.
  • ➤ MongoDB (27017) or Redis (6379) open to the whole Internet is not safe.
    • Bots scan for these all day. Allow them only from your app server.

🏢 Analogy

The IP address is a building's street address. The port is the flat number inside. The firewall is the guard at the gate with a list of who may visit which flat. The MAC address is like the name on one resident's ID card: the guard inside the building uses it, but it is never written on an envelope that travels across the city.

Common Mistakes

Three slips with listen addresses, open databases and MACs.

  • ➤ "It works on localhost but not from another device."
    • Check, in order: the address the server listens on, then the firewall rule for that port.
  • ➤ Exposing database ports to the Internet.
    • Restrict them to the IPs that really need them.
  • ➤ Thinking the MAC address travels across the Internet.
    • It is only used inside each local network.

Interview Q&A

The questions most often asked on this topic, with short answers to say out loud.

Q1. What is a port number and why is it needed?

➡️ A 16-bit number (0–65535) that identifies a program or service on a machine. The IP address finds the machine; the port lets one machine run many services, such as HTTPS on 443 and SSH on 22.

Q2. What is the difference between an IP address and a MAC address?

➡️ An IP address is a logical address that can change and is used to route data across networks. A MAC address is the hardware ID of a network card and is used only to deliver data inside the local network.

Q3. What is the difference between listening on 127.0.0.1 and 0.0.0.0?

➡️ 127.0.0.1 accepts connections only from the same machine. 0.0.0.0 accepts them on every IPv4 interface, so other devices can connect too. With no host, Node listens on ::, which covers IPv6 and IPv4.

Q4. What does a firewall do?

➡️ It filters inbound and outbound traffic using rules based on ports, IP addresses and programs. Inbound traffic is blocked by default except for replies and the ports you open on purpose.

Q5. How can one server port handle thousands of clients at once?

➡️ Each connection is identified by four values: client IP, client port, server IP and server port. Every client gets its own ephemeral port from its OS, so all their connections to port 443 are still different.

Practice

Try each one yourself before opening the answer.

P1. Name the port

HTTPS, MongoDB, SSH, Redis, PostgreSQL, DNS. Then say which range 8080, 443 and 55000 belong to.

Answer

443, 27017, 22, 6379, 5432, 53. Ranges: 8080 is registered, 443 is well-known, 55000 is dynamic / ephemeral.

P2. Debug EADDRINUSE

node server.js prints Error: listen EADDRINUSE: address already in use :::3000. What does it mean, and what are two fixes?

Answer

Another process is already listening on port 3000. (1) Find and stop it: netstat -ano | findstr :3000 on Windows or lsof -i :3000 on Linux/macOS shows its process ID. (2) Or start your server on another port.

P3. Debug a timeout

Your API on a cloud server works with curl localhost:4000 from inside the server but times out from your laptop. What do you check, in order?

Answer

(1) Is the server listening on all interfaces, not only 127.0.0.1? (2) Does the cloud firewall / security group allow inbound TCP 4000? (3) Does the server's own OS firewall allow it? (4) Are you using the server's public IP, not its private one?

⭐ Final Recap

💡 The IP finds the machine and the port (0–65535) finds the program; listen()'s host picks which interfaces accept connections; the MAC address only matters inside the local network; and the firewall decides which inbound and outbound traffic gets through.
